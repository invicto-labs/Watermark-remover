# ClearPage owner admin access

Admin access is optional and disabled until the seller provisions a username and
password hash on the payment service. There is no default password, public
registration, client-side free-use switch, or admin credential in customer builds.

## Private test setup

Run `python scripts/setup_test_payments.py --config ABSOLUTE-PRIVATE-PATH/settings.json`.
The settings file must be outside this repository. Enter your own `rzp_test_` API
credentials, admin username, support email and an admin password of at least 15
characters. The native setup window saves the password as a salted scrypt hash;
plaintext admin passwords are not saved. It reuses existing signing keys and keeps
all Razorpay and signing secrets private. It rejects live API keys. Keep this owner
utility and private settings off customer machines and out of customer ZIPs.

Start `python -m payment_service.run --config ABSOLUTE-PRIVATE-PATH/settings.json --test-only`.
Then launch the source desktop application with the separate test `billing.json`,
profile and `CLEARPAGE_PAYMENT_LOCAL_TEST=1`. The task's outputs contain launchers
for these steps. Never set the localhost test flag for a production customer app.

For a direct EXE, the private `scripts/owner_test_build.py` helper can pin this
exact localhost TEST service/public key and existing test profile. Its output
stays outside `release-assets`, is marked owner-test-only, and cannot pass the
customer release publisher. No server secrets are included. This is a local QA
application, separate from the customer build that requires the hosted HTTPS
payment configuration. Finish exporting in the old app before switching, then
sign in as admin again; a new login revokes the old session for that installation.

## Using the panel

1. Open ClearPage and select **Admin login** in its application header.
2. Enter the username and password you chose in the private setup window.
3. A verified login displays **Admin access is active**. Use the same cleanup,
   preview, review and export tools without spending document credits.
4. Use **Admin · signed in → Sign out of admin** to restore normal customer checks.

Internet is required even in admin mode. The session expires after one hour;
closing the application discards its local session. Sign in again when needed.
The server stores only a session-token hash and binds it to the installation.
Every document operation receives a signed, nonce-bound server decision; simply
changing the UI, a local flag or the local credit file does not authorize admin use.

Admin document access does not create purchases, allocate paid-document records,
or change the paid balance. After logout/expiry, a document opened only through
admin access needs another admin login or ordinary customer authorization.

## Hosting

Configure optional `CLEARPAGE_ADMIN_USERNAME` and `CLEARPAGE_ADMIN_PASSWORD_HASH`
only on the server (Render's private environment settings). Leave both unset to
disable owner login. Never place the hash, password or an admin session token in
`billing.json`, the website, GitHub Actions variables or the customer ZIP. Use
separate test/live owner credentials. The accepted hash format is Werkzeug scrypt
`scrypt:32768:8:1`, generated by the private setup utility.

Changing the password hash or username and restarting the service invalidates
existing sessions. A new login on an installation revokes its previous session.
Logout revokes the server token when reachable and always drops it locally. If
the server cannot be reached during logout, its previous token remains valid only
until its original expiry; the application reports that limitation.

The existing customer-controlled-code limitation still applies: this is server
authorization for the supplied application, not tamper-proof DRM for a modified EXE.

## Test evidence

`python -m unittest test_admin` checks wrong/forged credentials, disabled owner
accounts, rate limits, hashed tokens, account binding, expiry, password rotation,
logout, unchanged paid balances and real local HTTP authorization. No test owner
password is used for the seller's account. `node --test scripts/test_checkout.mjs`
checks test-card-only checkout versus normal live payment methods.

Successful mocked tests do not prove a Razorpay Test Mode payment was captured.
The actual test checkout and credit result are verified separately. No push,
public release, live payment or deployment is performed by these scripts.
